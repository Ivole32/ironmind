But there is a small catch I didn't understand at first: while reading `train-labels.idx1-ubyte`, I wanted to check that the data in the documentation is correct, so I read the first few bytes, which in my output are [0, 0, 8, 1, 0, 0, 234, 96, ...]. The documentation states that the first value should be the hexadecimal value 0x00000801 (2049), as you can see in the output. My output looks a bit different, though: when it says 0, the actual representation in hexadecimal is 00, 8 is 08, and so on. So as I understand it, every number is actually an 8-bit decimal representation. That made sense after a while, since Rust documents the value as some struct around a u8 when reading files. Since I read the train labels, the values after the header bytes are just the numbers of the assigned images in the train images file, in order.
