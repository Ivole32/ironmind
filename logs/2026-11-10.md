So in the last few days I've been busy and didn't do that much, but I came up with a simple approach to save the model in a file.

First, I started by finding out what the model file should contain and what the requirements for that are.

## Requirements
First, we need to store how many input neurons (= pixels per image) there are and also how many possible output neurons (0–9) there are. After that, the data needs to represent the weights between those neurons.

### In short
- store the input/output neuron count
- store the weights between neurons

## Approach
### Header
There is some data that can easily be saved in a header. This includes the count of input and output neurons and a simple magic number. For simplicity, I'm going to keep the initial structure of the IDX training files.

The header looks like this:
| [offset] | [type] | [description] |
|-|-|-|
| 0000 | 32 bit integer | Magic number |
| 0004 | 32 bit integer | Number of input neurons |
| 0008 | 32 bit integer | Number of output neurons |

### Data
For the raw weight storage, I didn't think of anything too complex. I can revise and improve this later.
To store the weights, we need to picture every point of a picture as a point `P(x|y)`, stored row by row. So when I thought about saving weights to `n` output neurons, the simplest approach was to just save every point `P`'s weights in natural row-wise order with incrementing output values. As this is a bit abstract, here is a simple representation:
```
P(0|0) => [Weight to output 0, Weight to output 1, ..., Weight to output n]
P(1|0) => [Weight to output 0, Weight to output 1, ..., Weight to output n]
.
.
.
```

Obviously, there is no need to save the coordinates of the points or the exact output values, as they can be read and interpreted with the header values at runtime.
